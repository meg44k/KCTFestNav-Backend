# KCTFestNav 要件定義書

## 1. プロジェクト概要
高専祭の来場者が、広大なキャンパス内で迷うことなく、イベントや展示を最大限楽しめるようにするためのナビゲーションWebアプリケーション。2D/3Dマップでの現在地表示や、リアルタイムな混雑状況・ライブ情報の提供を行う。

## 2. ターゲットユーザー
* **一般来場者**: スマートフォンでマップや企画情報を閲覧する（アプリインストール不要のWebブラウザ利用を想定）。
* **各企画の担当者（クラス・部活等）**: 自団体の混雑状況を更新する。
* **運営委員(学生会)**: 現在行われているライブイベントの情報更新や、システム全体（全企画のデータ）の管理を行う。

## 3. 機能要件

### 3.1 一般来場者向け機能（フロントエンド）
* **2Dマップ表示機能**
    * 学校配布の画像データをベースマップとして表示。
    * マップの拡大・縮小・スクロール操作。
    * ユーザーの「現在地」をピンで表示。(GPSを用いる)
* **3Dマップ表示機能**
    * 階層（フロア）が直感的にわかる3Dモデルのレンダリング。
    * 視点の回転・拡大・縮小。
    * 3D空間上での「現在地」のピン表示。(GPSを用いる)
* **スポット（展示・イベント）表示機能**
    * 2D/3Dマップ上に、企画が開催されている場所をアイコン等でマッピング。
    * タップすると、その場所で「何が行われているか（静的情報）」をモーダル等で表示。優先度低
* **リアルタイム情報表示機能**
    * **ライブ情報**: 現在メインステージ等で行われているライブやイベントをトップ画面やマップ上にハイライト表示。
    * **混雑度表示**: 各クラス・飲食ブース等の混雑度（例: 「空き」「普通」「混雑」の3段階など）をマップのピンの色や詳細画面で可視化。

### 3.2 管理・更新向け機能（バックエンド / 管理画面）
* **認証・認可システム（重要）**
    * 運営委員用アカウントと、各企画（クラス・ブース）担当者用アカウントの権限分離。
    * 各クラスは**自分のクラスの混雑度のみ**更新可能とする（他クラスのデータを勝手に変更できないようにする制限）。
* **混雑度更新機能**
    * 企画担当者がスマートフォンから数タップで現在の混雑度を変更できるシンプルなUI。
* **ライブ状態管理機能**
    * 運営委員が「現在のライブ」をリストから選択し、フロントエンドの表示を切り替える機能。

## 4. 非機能要件
* **レスポンシブ対応**: 来場者は歩きながらスマートフォンで利用するため、モバイルファーストなUI/UX設計。
* **パフォーマンス**: 3Dモデル（特にWebブラウザでの描画）の軽量化と、読み込み速度の最適化。
* **リアルタイム性**: 混雑度やライブ情報の更新が、リロードなし（または短いポーリング間隔）で来場者の画面に反映されること。

## 5. 技術スタック案（構成イメージ）

| 領域 | 技術候補 | 理由・備考 |
| :--- | :--- | :--- |
| **Frontend** | Vite.js | UIのコンポーネント化や状態管理（混雑度のリアルタイム反映など）が容易。 |
| **3D描画** | Three.js (React Three Fiber) | Web上で3Dモデル（glTF形式など）を滑らかに描画・操作するため。Minecraft由来のモデルデータも変換して利用可能。 |
| **Backend** | Go (Gin または Echo) | 処理が高速で、並行処理も得意。APIサーバーとして非常に優秀。 |
| **Database** | PostgreSQL または MySQL | 企画データ、ユーザー権限、混雑度履歴などのリレーションを厳格に管理するため。 |
| **インフラ** | Vercel (Front) + Cloud Run / Render (Back) | デプロイが簡単で、高専祭当日の急なトラフィック増にもスケールしやすい。 |
