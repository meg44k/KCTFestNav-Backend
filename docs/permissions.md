# ロールベースアクセス制御 (RBAC) 権限一覧

バックエンドAPIにおける各ロール（役職）が実行可能な操作の一覧です。
現在のユースケース層（Usecase）に実装されている権限チェックロジックに基づいています。

## ロールの種類
- **Admin**: 管理者（運営委員など）
- **Gakuseikai**: 学生会
- **Student**: 企画担当者（学生）
- **Member**: 一般ユーザー / その他
- **Guest**: 未ログイン（トークンなし）

---

## 権限マトリクス

| リソース | アクション (API) | Admin | Gakuseikai | Student | Member | Guest | 備考 |
|---|---|:---:|:---:|:---:|:---:|:---:|---|
| **アナウンス (Announce)** | 取得 (`GET`) | ◯ | ◯ | ◯ | ◯ | ◯ | |
| | 更新 (`PUT`) | ◯ | ◯ | ❌ | ❌ | ❌ | |
| **ブース (Booth)** | 取得 (`GET`) | ◯ | ◯ | ◯ | ◯ | ◯ | |
| | 作成 (`POST`) | ◯ | ❌ | ❌ | ❌ | ❌ | |
| | 更新 (`PUT`) | ◯ | ◯ | ⚠️ | ❌ | ❌ | Studentは自身に割り当てられたBoothのみ更新可能 |
| | 混雑度更新 (`PATCH`) | ◯ | ◯ | ⚠️ | ❌ | ❌ | Studentは自身に割り当てられたBoothのみ更新可能 |
| | 削除 (`DELETE`) | ◯ | ❌ | ❌ | ❌ | ❌ | |
| **ライブ (Live)** | 取得 (`GET`) | ◯ | ◯ | ◯ | ◯ | ◯ | |
| | 作成 (`POST`) | ◯ | ❌ | ❌ | ❌ | ❌ | |
| | 更新 (`PUT`) | ◯ | ◯ | ❌ | ❌ | ❌ | |
| | ステータス更新 (`PATCH`) | ◯ | ◯ | ❌ | ❌ | ❌ | |
| | 削除 (`DELETE`) | ◯ | ❌ | ❌ | ❌ | ❌ | |
| **ユーザー (User)** | ログイン (`POST`) | ◯ | ◯ | ◯ | ◯ | ◯ | |
| | 自身の情報取得 (`GET`) | ◯ | ◯ | ◯ | ◯ | ❌ | JWTトークン必須 |
| | 一覧/詳細取得 (`GET`) | ◯ | ◯ | ◯ | ◯ | ❌ | JWTトークン必須 (*1) |
| | 作成 (`POST`) | ◯ | ◯ | ◯ | ◯ | ❌ | JWTトークン必須 (*1) |
| | 更新 (`PUT`) | ◯ | ❌ | ❌ | ❌ | ❌ | |
| | 削除 (`DELETE`) | ◯ | ❌ | ❌ | ❌ | ❌ | |

> **(*1) ユーザーリソースの作成・取得についてのご注意**
> 現在の `UserUsecase` の `GetAll`, `GetByID`, `Create` メソッド内には、Admin権限を要求するコード (`reqUser.Role != domain.RoleAdmin`) が記述されていません。そのため、APIルーター上で `JWTAuth` は通過するものの、現状ではStudent等のロールであっても他ユーザーの取得や新規ユーザーの作成が技術的に可能な状態になっています。必要に応じてUsecase内に権限チェックの追加をご検討ください。
